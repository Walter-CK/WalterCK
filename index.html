Roster Scraper

Logs into McDonald's Australia's myRestaurant portal, reads your published roster, and turns it into a plain JSON feed so a phone automation can set your shift alarms without you opening the app.

Source on GitHub Bonus Shortcut

Why this exists

myRestaurant doesn't have an API, a calendar export, or a way to get notified when a new roster's published. If you want your shifts anywhere else like a Shortcuts automation, a calendar, an alarm then you're stuck opening the app and reading it yourself, every week.

This script does that reading for you: it drives a real browser through the actual login flow (McDonald's uses Microsoft SSO, so there's no simple form-post shortcut here), pulls the roster page's HTML once you're in, and parses out every shift into structured JSON.

Setting it up

  1. Get the files

    Clone or download the repo, then open a terminal in that folder.

    git clone https://github.com/Walter-CK/WalterCK.git
cd WalterCK/roster-scraper

  2. Install Python

    You need Python 3.10 or newer. If python --version in a terminal doesn't show that, grab it from python.org on Windows, tick "Add Python to PATH" during install.

  3. Install the dependencies

    pip install -r requirements.txt
playwright install chromium

    The second command downloads the actual browser Playwright drives. It's a one-time download, separate from any browser you already have installed.

  4. Add your login

    Open .env in any text editor and fill in your myRestaurant credentials (the same archID and password you use to log in normally)

    MYJOB_USERNAME=your.username@crew.mcd.com
MYJOB_PASSWORD=your-password
    This file never leaves your machine. It's listed in .gitignore, so a normal git push won't include it. Don't paste your real credentials anywhere else for security ofc.

  5. Run it

    python scrape_roster.py

    First run, open scrape_roster.py and set HEADLESS = False near the top. This pops up a visible browser window so you can watch the login happen and confirm it's working, rather than running invisibly. Once you've seen it succeed once, switch it back to True for normal use.

    A successful run ends with a line like Wrote 7 shifts across 2 week(s) to roster.json. If it fails partway through, it saves a screenshot and the page's HTML next to the script so you can see exactly what it was looking at when it broke.

What comes out

Every run produces a fresh roster.json, shifts grouped by the roster's own weekly periods:

{
  "last_updated": "2026-09-25T09:25:00+10:00",
  "weeks": [
    {
      "week_start": "21/09/26",
      "week_end": "27/09/26",
      "shifts": [
        {
          "date": "23/09/26",
          "start": "1:00 PM",
          "end": "4:00 PM",
          "location": "BERRINBA QLD",
          "hours": "3:00"
        }
      ]
    }
  ]
}

hours is a duration, not a decimal ("3:15" means 3 hours 15 minutes, not 3.15 hours.)

Getting it onto your phone

The script runs on a computer, but the point is having your shifts on your phone without opening anything. The way I've got it wired up:

Push to GitHub after each run

The script commits and pushes roster.json automatically if it changed, so the latest roster is always sitting in the repo with no manual upload step.

Runs on a schedule, in the cloud

A GitHub Actions workflow runs the scraper daily on GitHub's own servers, so a newly published roster shows up without your computer needing to be on. Full setup below.

Pull it into a Shortcut

An iOS Shortcut fetches roster.json straight from GitHub, reads through each week and shift, and sets an alarm ahead of each one. Private repo? The Shortcut authenticates with a fine-grained token scoped to read-only access on just this repo.

Running it with GitHub Actions

No always-on computer needed — GitHub runs the scraper for you, on a schedule, for free.

Task Scheduler or cron only work if your own machine is switched on at the right time. GitHub Actions runs the exact same script on GitHub's own servers instead, so it fires every morning whether your PC is asleep, off, or nowhere near you. This is what actually runs the scraper day to day now — not the local Task Scheduler setup described above.

  1. Add the workflow file

    Sits at .github/workflows/scrape.yml in the repo. It checks out the code, installs Python and Playwright, runs scrape_roster.py, and — if the roster changed — commits and pushes roster.json back to the repo itself.

  2. Add your login as repo secrets

    The workflow needs your myRestaurant credentials, but they can't sit in the repo as plain text the way your local .env does — GitHub Secrets exist for exactly this. In the repo: Settings → Secrets and variables → Actions → New repository secret.

    Secret nameValue
    MYJOB_USERNAMESame as your local .env
    MYJOB_PASSWORDSame as your local .env

    The workflow reads these in as environment variables when it runs — nobody with read access to the repo can see the values, only the workflow itself while it's running.

  3. The schedule

    Set with a cron expression, which GitHub Actions always reads in UTC — not your local time.

    schedule:
  - cron: "0 20 * * *"

    That's 20:00 UTC, which lands at 6:00 AM AEST the next day (Brisbane doesn't observe daylight saving, so this offset stays fixed year-round). Adjust the two numbers in the cron string if you want it running at a different time — first number is minutes, second is the UTC hour.

  4. Let it run on demand too

    Beyond the daily schedule, the workflow listens for two more triggers:

    on:
  schedule:
    - cron: "0 20 * * *"
  repository_dispatch:
    types: [rescan]
  workflow_dispatch:

    workflow_dispatch adds a manual "Run workflow" button in the repo's Actions tab — handy for testing without waiting on the schedule. repository_dispatch is what the Shortcut's "Re-scrape shifts" option uses: it sends a POST request to GitHub's API to kick off a run immediately, right from your phone.

  5. Set up the token for the Shortcut

    The Shortcut needs a GitHub token for two different jobs, so scope it for both: github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new. Set repository access to this repo only, then grant:

    PermissionAccessWhy
    ContentsRead-onlyLets the Shortcut fetch roster.json
    ActionsRead and writeLets the Shortcut's "Re-scrape shifts" trigger a workflow run
    Miss the Actions permission and re-scrape silently fails. Reading the roster still works fine with Contents-only access, but the dispatch call needs write access to Actions specifically to be allowed to start a run — without it you'll just get a 403 with no obvious explanation the first time you tap "Re-scrape shifts."

    Paste that same token into the Shortcut when it first asks for your GitHub API Key — it's used for both the roster fetch and the dispatch call.

  6. Check it actually ran

    Repo's Actions tab lists every run, scheduled or manual, with full logs — the same output you'd see running the script locally. If a run fails, the workflow uploads error_screenshot.png and error_page.html as downloadable artifacts on that run, same as a local failed run saves them next to the script.

What the Shortcut actually does

The Shortcut is the other half of this system. It reads roster.json and turns it into something you actually look at, without opening the myRestaurant app.

  1. Pulls your latest roster

    Fetches roster.json straight from GitHub and groups your shifts into This Week and Next Week, showing the day, start time and end time for each one.

  2. Sets alarms ahead of each shift

    Choose Create/Change Alarms, tell it how many minutes before a shift you want waking up, and it adds one alarm per upcoming shift automatically.

  3. Keeps your alarms in sync

    Run it again after a new roster's published and it clears out the old shift alarms before creating the new ones, so you're never left with a stale alarm for a shift that got moved or dropped.

  4. Triggers a fresh scrape on demand

    Choose Re-scan shifts and the Shortcut asks GitHub to run the scraper again right away — this is the repository_dispatch call the GitHub Actions workflow listens for above — instead of waiting for the next scheduled run, so you can check the moment a new roster gets published.

This is a template, not a plug-and-play app. The Shortcut is wired to my GitHub repo and my roster's JSON shape so using it yourself means pointing it at your own roster.json (and running your own copy of the scraper, or one adapted to your employer's portal). It's shared as a working example to adapt, not a one-tap install.
Heads up if you're adapting this yourself: myRestaurant's login flow is McDonald's own enterprise Microsoft SSO setup, not a simple username/password form so maybe expect to spend time in the script's selectors if your restaurant's portal renders slightly differently, or if Microsoft/McDonald's change the page layout later. The script logs each step as it goes, which makes it easier to see exactly where a run stalls.
